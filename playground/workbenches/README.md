# 工作台 Playground

在 RambleDesk 中打开**这个目录**，创建 Agent 会话，然后发送：

> 读取 PLAYGROUND.md，开始完整工作台测试。

后续每次提交反馈，Agent 会自动接着发起下一个场景，无须重复输入提示词。本轮覆盖四种工作台，其中逐项问答分别测试多题自定义回答和单题选择。

| 顺序 | 工作台 | 主要体验 |
| --- | --- | --- |
| 1 | Ramble 自由反馈 | 默认输入区顶部工具栏、同框录音/暂停、正文修改/撤销，可选截图、粘贴、附件和 Rambelle 整理 |
| 2 | 逐项问答 · 多题 | 选项、键入/语音自定义回答、跨框语音切换、字段附件标签、集中整理、返回修改和答案保存 |
| 3 | 逐项问答 · 单题选择 | 关闭自定义回答、切换选择、无补充正文提交 |
| 4 | 文稿审阅 | 每段批注续写与收起摘要、建议改写、每框工具栏与附件标签、跨字段语音整理、段落删除线与恢复、原稿内批注阅读与续写 |
| 5 | 网页评审 | 真实网页浏览/元素选择、就地批注与评审记录、桌面/移动视口、展开/分栏保留页面、整体反馈浮层、SPA 回访及提交后只读 |
| 收尾 | Ramble 汇总确认 | 查看本轮实际结果，确认完成或补充问题 |

这是走真实保存、提交和 Agent 续接的人工体验，共 **5 次场景提交 + 1 张汇总卡**。它不代替自动化测试；未实际体验的可选项会记为“未验证”。

## 准备条件

- 运行包含这四种工作台、每输入框顶部工具栏及右下角 Rambelle 整理区域的本分支应用版本。只有源码更新、仍运行旧安装版时，可能缺少新交互；Agent 会先检查工作台类型。共享输入与整理的具体交互仍需你在应用中体验确认。
- 通过 RambleDesk 内的 Agent 会话运行，由应用注入反馈命令；普通终端或外部聊天不具有同一会话能力。
- 辅助脚本只使用 Node.js 内置模块，不需要安装依赖。网页样例服务需要 Node 18+；没有 Node 时，Agent 可手工准备运行文件，但网页阶段还需要已有的可用开发服务器。

进入第 5 步前，Agent 用 `node web-review-server.mjs start '<本轮绝对目录>'` 启动独立的 loopback 样例服务，并把实际端口写入本轮 `05-web-review.json`。无需另开 Vite，也不要直接发送 fixture 中的占位地址。页面复用仓库中固定的 Atelier HTML/CSS/JS 和 review bridge，能实际点击、滚动、切换路由和选择元素。服务在 Agent 交接后继续运行，结束或取消本轮时由 Agent 停止。

只体验新工作台时，在本目录会话发送：

> 读取 PLAYGROUND.md，只测试网页评审工作台。

Agent 会为这一轮只准备网页阶段，结束后给出汇总；不会替你填写意见。

每个请求默认向右侧正文输入。每个输入框顶部统一提供麦克风、截图、粘贴和附件；同框再次点击麦克风会暂停，点击另一框麦克风保持录音并切换后续语音，已开始的语音仍回到原框。右下角只保留左侧 Rambelle 大头像、右侧状态对话气泡和有待整理语音时出现的整理按钮。

准备测试整理时，请在至少两个位置各录一段，再键入和粘贴各一句。Rambelle 区域应在有待整理语音时显示“整理 N 段语音”，忙碌时显示处理状态，失败时可重试，成功后收起按钮；没有待整理内容时不保留空按钮。整理后语音各自原位更新，键入和粘贴文字不受影响。再从答案或批注的工具栏加一张截图或一个文件，检查附件标签留在原字段并可预览，打开采集窗口后换框也不改变归属。没有识别、整理或采集能力时可继续键入完成本轮，对应体验记为未验证。

## 继续与重跑

中断后在**原会话**发送：

> 读取 PLAYGROUND.md，继续上一轮工作台测试。

完成后重新发送开始提示词即可创建新一轮。取消任意请求会中止这一轮；需要重跑时明确说“开始新一轮工作台测试”。同一目录同时只跑一轮，不要在多个会话共用运行记录。

每轮输入、请求 ID、实际响应和报告放在 `.runs/<run-id>/`，不会进入 Git。固定场景在 `fixtures/`，人工操作清单在 `materials/`。所有文案都是测试材料；其中夸大表述和冗余段落是故意留给审阅的。

只校验材料、不发起请求：`node prepare.mjs check`。

准备流程和样例服务的自动检查：`node --test web-review-server.test.mjs`。测试使用隔离运行记录，验证服务启停与 URL 恢复，不提交人类反馈。

## 历史运行兼容

仅恢复旧轮时使用本节。按旧 `run.json.stages` 恢复，不追加网页阶段、不重新编号、不替换已有请求 ID 或汇总卡路径。旧运行中保存的 `single_choice` 请求继续按旧结果格式恢复，不转换已有请求；保留 `materials/03-single-choice.md` 的路径，避免已有运行的绝对附件路径失效。新轮始终使用表中的 `questions` 场景和 `03-single-question.json`，不要复制历史材料创建请求。
