# 工作台 Playground

在 RambleDesk 中打开**这个目录**，创建 Agent 会话，然后发送：

> 读取 PLAYGROUND.md，开始完整工作台测试。

后续每次提交反馈，Agent 会自动接着发起下一种工作台，无须重复输入提示词。

| 顺序 | 工作台 | 主要体验 |
| --- | --- | --- |
| 1 | Ramble 自由反馈 | 正文、修改/撤销，可选语音、截图、附件 |
| 2 | 逐项问答 | 选项、自定义回答、返回修改、答案保存 |
| 3 | 方案单选 | 切换选择、无补充正文提交 |
| 4 | 文稿审阅 | 文字批注、建议改写、段落标记、定位和解决状态 |
| 收尾 | Ramble 汇总确认 | 查看本轮实际结果，确认完成或补充问题 |

这是走真实保存、提交和 Agent 续接的人工体验，共 **4 次场景提交 + 1 张汇总卡**。它不代替自动化测试；未实际体验的可选项会记为“未验证”。

## 准备条件

- 运行包含这四种工作台的本分支应用版本。只有源码更新、仍运行旧安装版时，可能缺少文稿审阅；Agent 会先检查能力并停止提示。
- 通过 RambleDesk 内的 Agent 会话运行，由应用注入反馈命令；普通终端或外部聊天不具有同一会话能力。
- 辅助脚本只使用 Node.js 内置模块，不需要安装依赖。没有 Node 时，Agent 可按 PLAYGROUND.md 手工创建同样的运行文件。

## 继续与重跑

中断后在**原会话**发送：

> 读取 PLAYGROUND.md，继续上一轮工作台测试。

完成后重新发送开始提示词即可创建新一轮。取消任意请求会中止这一轮；需要重跑时明确说“开始新一轮工作台测试”。同一目录同时只跑一轮，不要在多个会话共用运行记录。

每轮输入、请求 ID、实际响应和报告放在 `.runs/<run-id>/`，不会进入 Git。固定场景在 `fixtures/`，人工操作清单在 `materials/`。所有文案都是测试材料；其中夸大表述和冗余段落是故意留给审阅的。

只校验材料、不发起请求：`node prepare.mjs check`。
