# 工作台 Playground

在 RambleDesk 中打开**这个目录**，创建 Agent 会话，然后发送：

> 读取 PLAYGROUND.md，开始完整工作台测试。

后续每次提交反馈，Agent 会自动接着发起下一个场景，无须重复输入提示词。本轮用十个场景覆盖八种工作台，其中逐项问答分别测试多题自定义回答和单题选择，视觉反馈分别测试空白画布和图片背景。

| 顺序 | 工作台 | 主要体验 |
| --- | --- | --- |
| 1 | Ramble 自由反馈 | 默认输入区顶部工具栏、同框录音/暂停、正文修改/撤销，可选截图、粘贴、附件和 Rambelle 整理 |
| 2 | 逐项问答 · 多题 | 选项、键入/语音自定义回答、跨框语音切换、字段附件标签、集中整理、返回修改和答案保存 |
| 3 | 逐项问答 · 单题选择 | 关闭自定义回答、切换选择、无补充正文提交 |
| 4 | 文稿审阅 | 每段批注续写与收起摘要、建议改写、每框工具栏与附件标签、跨字段语音整理、段落删除线与恢复、原稿内批注阅读与续写 |
| 5 | 网页评审 | 真实网页浏览/元素选择、精简底部批注与评审记录、图标视口切换及居中手机画布、网页工具栏全屏入口、普通工作台/独立评审页签往返、会话列表切换、整体反馈浮层、SPA 回访及提交后只读 |
| 6 | 终端试用 | 真实 CLI、从体验 Markdown 复制命令、中文/彩色输出、交互提示、方向键/Ctrl+C、输出引用、全屏页签、停止/退出后重开、多轮记录与提交收尾 |
| 7 | 视觉反馈 · 空白画布 | 简笔、箭头、矩形、文字、底色、撤销／重做、缩放、恢复与合成图片 |
| 8 | 视觉反馈 · 图片背景 | 在固定图片上圈画、补充意见、保留原图与提交标注 |
| 9 | 差异评审 | 文件切换、修改前后行／范围／改动块批注、共享输入与精确结果 |
| 10 | 拖动排序 | 功能优先级拖动、手柄键盘排序、编辑名称、删除与恢复、草稿恢复和只读结果；普通视图无全屏入口 |
| 收尾 | Ramble 汇总确认 | 查看本轮实际结果，确认完成或补充问题 |

这是走真实保存、提交和 Agent 续接的人工体验，共 **10 次场景提交 + 1 张汇总卡**。它不代替自动化测试；未实际体验的可选项会记为“未验证”。

完整新轮的请求标题由准备脚本按实际场景生成 `x/N` 编号；固定材料不写总场景数。新增普通类型按用例发现加入新轮，无须改写其他类型的材料；恢复旧轮仍保留已发送标题和阶段。

## 准备条件

只体验终端工作台时，在本目录 Agent 会话中发送「读取 PLAYGROUND.md，只测试终端工作台」。Agent 使用 `node prepare.mjs new terminal` 准备独立用例，自动将起始目录解析为本目录的绝对路径，然后发送真实 terminal 请求。固定 `materials/terminal-demo.mjs` 提供帮助、问候、方向键菜单和错误提示，不需要安装依赖。终端运行在 RambleDesk 后端主机。

- 运行包含这八种工作台、每输入框顶部工具栏及右下角 Rambelle 整理区域的本分支应用版本。只有源码更新、仍运行旧安装版时，可能缺少新交互；Agent 会先检查工作台类型。共享输入与整理的具体交互仍需你在应用中体验确认。
- 通过 RambleDesk 内的 Agent 会话运行，由应用注入反馈命令；普通终端或外部聊天不具有同一会话能力。
- 辅助脚本和终端 CLI 样例只使用 Node.js 内置模块，不需要安装依赖。网页样例服务需要 Node 18+；没有 Node 时可手工准备运行文件，但网页阶段需要已有开发服务器，终端样例需要安装 Node 后才能体验。

进入第 5 步前，Agent 用 `node web-review-server.mjs start '<本轮绝对目录>'` 启动独立的 loopback 样例服务，并把实际端口写入本轮 `05-web-review.json`。无需另开 Vite，也不要直接发送 fixture 中的占位地址。页面复用仓库中固定的 Atelier HTML/CSS/JS 和 review bridge，能实际点击、滚动、切换路由和选择元素。服务在 Agent 交接后继续运行，结束或取消本轮时由 Agent 停止。

网页请求先显示普通工作台。网页工具栏中紧邻“选择元素”的全屏评审按钮会打开独立页签，页签位于会话列表右侧；评审时仍能从左侧切换会话。普通工作台与评审页签共享同一请求的草稿和网页状态，关闭评审页签回普通工作台后可继续编辑。元素批注固定浮在当前工作台底部居中，只显示“批注 N”、意见框及删除、收起、输入工具，长意见在框内滚动，小屏限制宽高。元素捕获信息仍完整保存，终态历史可展示。桌面／手机按钮只显示图标与 tooltip，不显示尺寸文字；手机画布固定为 390 × 844 CSS px 并水平居中，这些数值用于验收与数据核对。

只体验网页评审时，在本目录会话发送：

> 读取 PLAYGROUND.md，只测试网页评审工作台。

Agent 会为这一轮只准备网页阶段，结束后给出汇总；不会替你填写意见。

每个请求默认向右侧正文输入。每个输入框顶部统一提供麦克风、截图、粘贴和附件；同框再次点击麦克风会暂停，点击另一框麦克风保持录音并切换后续语音，已开始的语音仍回到原框。右下角只保留左侧 Rambelle 大头像、右侧状态对话气泡和有待整理语音时出现的整理按钮。

准备测试整理时，请在至少两个位置各录一段，再键入和粘贴各一句。Rambelle 区域应在有待整理语音时显示“整理 N 段语音”，忙碌时显示处理状态，失败时可重试，成功后收起按钮；没有待整理内容时不保留空按钮。整理后语音各自原位更新，键入和粘贴文字不受影响。再从答案或批注的工具栏加一张截图或一个文件，检查附件标签留在原字段并可预览，打开采集窗口后换框也不改变归属。没有识别、整理或采集能力时可继续键入完成本轮，对应体验记为未验证。

## 继续与重跑

中断后在**原会话**发送：

> 读取 PLAYGROUND.md，继续上一轮工作台测试。

完成后重新发送开始提示词即可创建新一轮。取消任意请求会中止这一轮；需要重跑时明确说“开始新一轮工作台测试”。同一目录同时只跑一轮，不要在多个会话共用运行记录。

每轮输入、请求 ID、实际响应和报告放在 `.runs/<run-id>/`，不会进入 Git。固定场景在 `fixtures/`，人工操作清单在 `materials/`。所有文案都是测试材料；其中夸大表述和冗余段落是故意留给审阅的。

只校验材料、不发起请求：`node prepare.mjs check`。每个附件必须同时声明 `path` 和请求合同必填的 `file_name`；准备时只将路径解析为绝对路径，保留明确的附件名。检查会拒绝缺失或无效的名称，再核对文件存在；新轮输入不合法时不创建运行记录。图片背景的 `image_file_name` 必须精确匹配对应附件的 `file_name`。

准备流程和样例服务的自动检查：`node --test prepare.test.mjs web-review-server.test.mjs`。测试使用隔离运行记录，验证用例发现、恢复约束、服务启停与 URL 恢复，不提交人类反馈。

## 新类型与开发演练

只体验拖动排序时，在本目录 Agent 会话发送「读取 PLAYGROUND.md，只测试 sort 工作台」。Agent 使用 `node prepare.mjs new sort`，按 `materials/sort.md` 检查拖动、草稿恢复和最终顺序。

`prepare.mjs` 自动发现 `fixtures/` 的 JSON，普通新增类型不需要改脚本。`node prepare.mjs check <type>` 校验材料，`new <type>` 只准备该类型。类型和提交结果仍需与真实后端的发现/schema 核对，脚本不验证业务完成条件。

仅开发构建可用的 `rating_review` 位于 `fixtures/development/`，默认完整十场景不包含它。使用 `node prepare.mjs check rating_review --development` 或 `new rating_review --development`，按 `materials/rating-review.md` 体验。前后端开关及教程见[新增工作台](../../docs/workbench/adding-a-workbench.md)。正式应用缺少此类型时不能替换成自由反馈或声称通过。

## 历史运行兼容

仅恢复旧轮时使用本节。按旧 `run.json.stages` 恢复，不追加网页或终端阶段、不重新编号、不替换已有请求 ID 或汇总卡路径。旧运行中保存的 `single_choice` 请求继续按旧结果格式恢复，不转换已有请求；保留 `materials/03-single-choice.md` 的路径，避免已有运行的绝对附件路径失效。新轮始终使用表中的 `questions` 场景和 `03-single-question.json`，不要复制历史材料创建请求。
