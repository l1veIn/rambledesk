# RambleDesk 产品宪章

本文保存稳定的产品约束；当前旅程见[产品文档](PRODUCT.md)，对象定义仅见[术语表](TERMINOLOGY.md)。普通实现不得静默偏离本文。

## North Star

宿主智能体可以正式请求一个人去真实体验某个产品；人收到清晰任务、自由记录过程，并把带证据的反馈作为持久化产物交回宿主，而不需要手动搬运聊天上下文。

主要用户是在本机使用 Coding Agent 的个人开发者或产品构建者，同时承担产品操作者和第一位体验者。产品价值在于把真实使用、观察、判断和表达接入迭代循环。

## 产品原则

1. **人类是体验参与者。** 请求应要求真实操作或主观判断；普通确认、权限审批和短问答不是主要价值。
2. **请求侧结构化，回复侧自由。** 宿主提供背景和可执行动作；人类无需先把反馈整理成宿主偏好的格式。
3. **业务事实独立于连接。** 请求先持久化再返回；草稿与结果可恢复。断线、超时或客户端关闭不得隐式改变请求的业务含义。
4. **证据可追溯。** 人类提交的反馈形成不可变 Feedback Package；Cooking 不得覆盖原稿、编造事实或删除负面判断。聊天、通知和 UI 状态不能成为唯一事实来源。
5. **本地优先、边界明确。** 数据默认在本机，服务只绑定 loopback。云同步、远程入口和团队权限不能以半成品方式混入。
6. **宿主中立。** 反馈合同不依赖某个厂商的私有会话模型；关联字段不是认证凭据。外部反馈适配器与 Agent 会话管理分别承担职责。
7. **先保护闭环，再扩展能力。** 文本、持久化、恢复和可靠交付优先于新增输入能力与功能数量。能力声明和握手不代替真实闭环验收。

RambleDesk 可以通过 ACP 启动、交互和管理外部 Agent Session；推理和工具执行仍属于外部 Agent Backend。工作目录是执行配置，不建立源码 checkout 管理模型，也不授权 RambleDesk 自行规划并修改用户代码。

`User_0` 只表示构建者把自己当作第一个体验者的起源方法论，不是产品名、领域对象、协议命名空间、目录约定或权限角色。

## 不可妥协条件

- 创建、重试、读取、取消与发布具有明确的持久身份和幂等行为；同一请求不能因重试产生重复反馈包。
- 人类能查看、编辑并提交至少纯文本反馈；故障不能丢失已保存的原稿和结果。
- 宿主断线或重启后可以凭原 `request_id` 取得结果，不依赖无限存活的 HTTP 连接。
- 本地入口验证 credential、Host 和 Origin；业务关联身份不能代替认证。
- 核心状态迁移有自动化证据，设备、平台和原生手势另做真实验收。

## 决策优先级

1. 不丢请求、草稿和已提交反馈。
2. 人类清楚宿主要什么、当前发生了什么。
3. 宿主能确定地关联并取得结果。
4. 跨宿主一致性。
5. 交互速度和视觉完成度。
6. 功能数量。

## 宪章修改规则

修改产品约束时记录真实信号、失效条款、替代条款，以及对协议、数据和里程碑的影响。普通实现便利、依赖偏好或未经验证的竞品能力不足以修改 North Star。

2026-09-04 的 ACP 修订允许托管外部 Agent，会话仍可跨任务持续，反馈仍形成持久请求和不可变证据；它没有授权内置推理引擎或 checkout 管理。修订原因与影响保留在 [ADR 007](adr/007-acp-managed-sessions.md)。本次文档收拢仅移除重复定义和历史功能清单，不改变这些约束。
