# RambleDesk 产品宪章

> 状态：Active  
> 版本：v1 · 2026-07-29  
> 作用：约束产品、协议和工程决策。普通实现不得静默偏离本文。

## 1. North Star

> Agent 可以正式请求一个人去真实体验某个产品；人收到清晰任务、自由记录过程，并把带证据的反馈作为持久化产物交回 Agent，而不需要手动搬运聊天上下文。

RambleDesk 的价值不在“语音转文字”，也不在“让人审批 Agent”。它把人类真实使用、观察、判断和表达接入 Agent 的持续迭代循环。

## 2. 目标用户与工作

MVP 的主要用户是：

- 在同一台电脑上运行 Coding Agent 和 RambleDesk 的个人开发者或产品构建者；
- 同时承担产品操作者和第一位体验者；
- 希望 Agent 在需要真实体验时发出正式请求，而不是把问题埋在聊天中。

用户雇用 RambleDesk 完成三件事：

1. 在不盯着 Agent 对话的情况下收到体验请求；
2. 按明确清单真实操作目标软件，并用文字、语音和截图自由反馈；
3. 提交一次后，让原 Agent 能可靠取得结构化反馈并继续工作。

## 3. 产品原则

### 3.1 人类是体验参与者，不只是审批按钮

请求必须要求真实操作或主观判断。普通确认、权限审批和短文本问答不是 RambleDesk 的主要价值。

### 3.2 请求侧结构化，回复侧自由

Agent 负责提供客观背景和可直接执行的动作。人类可以 ramble，不需要先把反馈整理成 Agent 期待的格式。

### 3.3 业务状态独立于连接状态

反馈请求、草稿和结果必须先落盘。MCP 连接断开、客户端超时或工作台重启，不得隐式删除或改变请求的业务含义。

### 3.4 产物优先于聊天

一次完成的反馈必须形成可携带、可引用、可审计的 Feedback Package。聊天文本、通知和 UI 状态不能成为唯一事实来源。

### 3.5 Local-first 与明确边界

MVP 服务于同机 Agent，默认只监听 loopback，数据默认保存在本机。远程 Agent、云同步和多人权限不以半成品形式混入 MVP。

### 3.6 Agent-neutral

协议不得依赖 Codex 或 Claude Code 的私有会话模型。`agent` 和 `session_id` 只是调用方提供的关联信息，不是认证凭据。

### 3.7 先打通最小闭环，再增加输入能力

文本反馈闭环、持久化和恢复优先于语音、系统级截图、历史检索和视觉打磨。任何新增能力不得破坏已验证的闭环。

## 4. User_0 的位置

`User_0` 是 RambleDesk 的起源方法论：构建者把自己当作第一个真实用户。

它不是：

- 产品名；
- 核心领域对象；
- MCP 协议命名空间；
- 默认文件目录名；
- 对其他体验者的角色或权限模型。

产品和代码统一使用 RambleDesk、Operator、Feedback Request、Feedback Package 等中性词汇。`User_0` 只保留在方法论、历史和 dogfooding 示例中。

## 5. 核心领域词汇

| 词汇 | 定义 |
|------|------|
| Operator | 使用 RambleDesk 完成体验并提交反馈的人 |
| Agent | 发出请求并消费结果的 MCP 客户端一侧 Agent |
| Project | 反馈关联的本机工作区；由稳定 `project_id` 标识 |
| Session | Agent 提供的任务/会话关联信息；键为 `project_id + agent + session_id` |
| Feedback Request | 一次持久化体验请求 |
| Invocation Attempt | 一次 MCP 调用尝试；可断开、取消或完成 |
| Draft | 尚未提交的文字和附件 |
| Feedback Package | 已完成请求的不可变交付目录 |

## 6. MVP 不可妥协条件

MVP 必须做到：

- 本地桌面工作台可以启动、停止并显示 MCP 状态；
- Agent 可以创建带背景和动作清单的请求；
- 请求在收到响应前已经持久化；
- Operator 可以查看、编辑并提交至少纯文本反馈；
- 提交生成稳定 Feedback Package；
- Agent 可以在断线或重启后通过 `request_id` 取得同一结果；
- 重复调用不会生成重复请求或重复反馈包；
- 工作台只绑定 loopback，并验证 Host/Origin 和访问令牌；
- 所有核心状态迁移都有自动化测试。

语音和系统级截图不是首个可运行切片的阻塞项。

## 7. MVP 明确不做

- 远程或云端 MCP 服务；
- 多用户、团队协作和权限系统；
- 内置 Agent runtime；
- 自动修改用户项目；
- 通用听写或全局语音输入；
- 对反馈内容进行不可追溯的 LLM 重写；
- 移动端 App；
- 依赖无限 HTTP 连接才能正确工作。

## 8. 决策优先级

发生冲突时按以下顺序取舍：

1. 不丢请求、草稿和已提交反馈；
2. Operator 清楚知道 Agent 要什么、当前发生了什么；
3. Agent 能以确定方式关联并取得结果；
4. 跨客户端兼容；
5. 交互速度和视觉完成度；
6. 功能数量。
