## 产品定义

**RambleDesk 的 ACP 交互对齐 Codeg，并默认内置 RambleDesk 工作流。**

- 外部智能体会话具有原有的 Ramble 会话页面。
- 内部 ACP 会话具有同样的 Ramble 页面，以及独立的 Agent 会话页面。
- 两种页面是同一业务会话的平级视图，各自由 workspace tab 承载，通过明确入口互相跳转。
- 新建页与 Agent 对话页是同一个 tab 的前后状态。左侧列表记录正式会话，顶部 tab 承载视图。

## 已确认的行为

### 智能体管理

- Agents 以设备上的智能体为主对象，展示安装、版本、认证与接入状态。
- 安装或配置完成即可用于新建会话，移除额外的“使用此智能体”步骤。
- 自定义 ACP 入口通过“添加智能体”进入同一列表；启动参数与环境变量属于详情中的高级设置。
- 建立明确的目录与连接身份关联，逐步替代通过命令路径猜测身份；兼容已有配置和会话。
- 原有 MCP、Skills、原生插件由各智能体的配置机制加载。默认反馈能力由 RambleDesk 的会话运行时提供。
- 外部工具接入仍服务“从终端或其他客户端呼叫 RambleDesk”，保留已有闭环。

### 统一托管反馈

- 正式应用的可执行文件支持无界面 `feedback request/get/recover` 命令；独立 CLI 不是用户前置依赖。
- 通用命令通过 HTTP JSON 调用 local-server 的会话专用入口，不要求智能体支持 MCP 或特定插件 SDK。
- 服务端从运行时签发的凭据确定会话归属；调用方不能选择归属，也不能缺少身份时回退到外部全局入口。
- 保留持久 request_id、幂等、反馈包、投递记录、撤销与原会话恢复。请求返回后结束当前轮次，用户提交后由 RambleDesk 续接；不引入长期 shell 等待或轮询。
- 默认内置工作流说明：何时请用户体验/判断、如何创建请求、结束当前轮次、读取反馈并继续。ACP v1 无统一 system prompt 字段，以应用提供的会话上下文实现，恢复时刷新必要说明。
- 只有实际可执行通用命令并访问会话 API 的启动方式才算反馈就绪。旧 MCP/Pi/dsh 出口不得抢走托管会话反馈。

### 新建会话

- “新建会话”立即打开临时草稿 tab，可选择 Agent、工作目录并输入任务，复用最近选择。
- 选择齐全后自动预连接，取得真实模型、思考强度和模式选项；连接过程不阻塞编辑。
- 首次发送前不出现在正式 session 列表。准备状态可以有内部持久记录和 ACP session ID。
- 首条真实用户消息被接受并持久化时转为正式会话，沿用同一 ACP session、同一 tab，自动命名。
- 引导指令不是用户任务，不计为首次发送，也不参与命名。自动标题失败不阻塞工作，手动改名后保留用户选择。
- 发送前更换 Agent/目录保留草稿并重建准备连接，丢弃旧连接的迟到结果。
- 关闭未发送 tab 回收连接与凭据；有输入内容可保留草稿。已开始会话的关 tab 仍只关闭视图。

### 页面与加载边界

- Ramble 请求详情、Ramble 会话页、Task Preview 恢复聚焦请求的界面，移除内嵌 Agent 对话/配置/恢复控制器。
- 内部 ACP 来源请求只增加“查看 Agent 会话”按钮，基于可信来源 ID 打开或聚焦唯一 Agent tab。
- 保留请求自身的提交、投递异常及删除锁定等必要状态，通过轻量数据提供。
- 浏览请求不得加载 Agent 历史或全部 Agent 配置；打开 Agent tab 才加载相应对话。
- 保留草稿、滚动与展开状态；非活动页面停止重渲染，后台运行继续由后端负责。

### Agent 页面

- 按真实 turn 组织用户消息、工作过程和最终回答，参考 Codeg 的 `CompletedTurnContent`、`TurnStats`、`ComposerContextUsage`。
- 思考、工具调用和中间工作记录归入过程区；已完成过程可整体收起，最终回答可见，重内容延迟挂载。
- 当前工作进度、错误、取消和待处理权限不能被折叠隐藏。尊重用户手动展开状态。
- 每轮有复制与真实完成时间，过程区展示工作耗时；保持历史分页、跨分页轮次和滚动锚点正确。
- 输入器承载模型/思考/模式控制。上下文占用与 token 消耗分别表达，仅展示 Agent 实际提供的统计。

## 验收标准

- 两个并发 ACP 会话的请求、反馈、恢复和删除互不影响；缺少/撤销凭据不能创建或读取反馈。
- 同 request_id 重试不重复请求；投递结果不明时不盲目重放。
- 桌面二进制命令不启动 UI、不自行启动第二个后端、不打开业务数据库，stdout/退出码稳定。
- 新建未发送不进列表；第一次发送仅转正一次；快速换 Agent/目录、关闭、重开不会串会话或遗留准备资源。
- Agent tab 和 Ramble tab 可以同时打开，互相跳转不丢草稿，同一 Agent tab 不重复创建。
- 请求页和 Task Preview 不调用 Agent 历史查询；长对话仅按需渲染，工作过程折叠真正减少挂载。
- turn 最终回复、工具更新、完成时间、分页与重连无丢失/重复；无 usage 不显示虚构数值。
- Rust DTO 变更重新生成前端类型；执行相关测试、Svelte 检查、合同检查、模块边界与格式检查。
- 最终执行适当的集成检查并进行可用环境内的 UI QA。实际模型、操作系统和安装包验证分别记录；夹具不冒充真实 Agent 或跨平台验收。
