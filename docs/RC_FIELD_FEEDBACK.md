# 问题反馈与诊断

优先记录推荐的 ACP 集成流程在实际使用中的问题。诊断默认写入本机，用户从“设置 → 关于”主动导出诊断 ZIP 后再分享；没有自动上传或远程埋点服务。

## 给测试用户的说明

按平时的工作方式使用即可，优先走新手引导和“新建会话”，默认使用 ACP 集成流程。希望继续在自己的 Agent 应用或 CLI 中工作时，可在设置中启用外部适配器，让 RambleDesk 接收反馈请求并返回回复。

遇到失败、长时间等待、会话状态异常或崩溃后：

1. 记下大致发生时间、所在页面、点击的按钮，以及预期和实际结果。特别注明是否重试过、重试是否恢复。
2. 从“设置 → 关于”导出最近 24 小时的诊断包；问题发生在更早时间则选最近 7 天或全部。尽量在问题发生后尽快导出。重启后的应用仍可导出此前保留的记录。
3. 反馈中附上 ZIP、RambleDesk 版本、操作系统、所用 Agent 名称。截图或录屏可用于补充视觉问题，自行遮挡不希望分享的内容。

如果后端尚未启动，诊断包可能无法导出：使用启动错误提示中的“打开日志目录并退出”，提供日志及发生时间。界面组件加载失败时可以复制错误信息；工作台加载失败时可以从错误页打开关于/诊断。版本回退的范围和操作前提见 [数据兼容说明](DATA_COMPATIBILITY.md)。

可直接使用这份反馈模板：

```text
RambleDesk 版本：
系统和 Agent：
发生时间（含时区）：
操作步骤：
预期结果 / 实际结果：
是否稳定复现，重试或重启后是否恢复：
诊断 ZIP：
```

诊断包不主动执行程序扫描、ACP 检查或适配器检测。反馈中的操作描述仍然必要：埋点记录阶段和结果，不包含任务正文、聊天回复、截图附件、模型密钥或环境变量值。

## 诊断覆盖

| 链路 | 可以从诊断中看到什么 |
| --- | --- |
| 启动与界面 | 前端挂载、工作台初始化、应用事件订阅失败、事件积压后重新读取快照、未处理的前端异常类别 |
| 新手引导 | 可用步骤、进入和离开步骤、停留时间、跳过、重启续接目标、结束时是否已选择 Agent、打开新会话的结果 |
| 数据、语音和权限 | 数据位置选择结果及是否需重启、模型列表和下载结果、权限步骤是否可用、通知授权结果、Cooking/声音选项是否启用 |
| Agent 管理 | 手动与引导触发的扫描、缓存复用、安装发现与连接检查结果、单次耗时、配置保存和删除、组件安装及取消、安装后的单目标复检 |
| ACP 运行 | 程序启动、协议初始化、连接结束、超时、主动关闭，以及稳定错误类别 |
| 会话 | 准备、草稿转为正式会话、首次发送、首个有效 Agent 事件、回合完成、取消/停止、权限响应、归档和删除 |
| 外部适配器 | 仅用户进入外部适配器设置页后，记录访问、检查结果和门控；ACP 集成流程不触发这些检查 |

首响应表示第一个被当前回合接受的 Agent 事件，不一定是可见的回答文本。`session.send` 成功表示请求已被接受；实际运行结果要继续看同一会话的 `session.turn`。流式内容不逐 token 写日志，只记录首响应和终局计数。

## 收到 ZIP 后如何分析

1. 先看 `manifest.json`：版本、生成时间、时间范围、应用启动标识，以及事件和日志的覆盖/截断信息。
2. 看 `event-summary.json`：按活动统计的结局、失败类别、耗时分布，以及只有开始而没有结局的操作数量。
3. 用 `events.jsonl` 还原前端时间线，以 `appSessionId` 和 `operationId` 关联开始与结局。`details` 只有双方共享白名单中的状态、数字和布尔值；`events.csv` 是同一时间线的表格版本。
4. 在 `logs/` 搜索 `agent operation`、`operation_id`、`subject_id`、`related_id`，沿 native 会话、运行实例和回合标识追踪具体阶段。非 UUID 标识使用稳定摘要，原始命令行、路径、stderr 和环境值不进入新增埋点。
5. 对照 `runtime.json`、`environment.json`、`models.json`、`requests.json` 和用户的操作时间，区分设备准备、连接、运行和界面状态问题。

没有结局的操作只能说明记录不完整：可能是应用退出、进程崩溃、仍在进行、时间窗口截断或日志保留上限，不能直接算作失败。诊断摘要中的耗时是已记录的操作样本，不代表所有用户的总体指标。

事件文件保留最多约 4 MiB、20,000 条；导出最多 7 个日志文件，每个取最多 1 MiB 尾部，以及最多 2,000 条请求元数据。包中明确记录读取范围、截断和被省略的记录。旧版前端异常日志的自由文本在导出时省略。前端诊断写入设有并发上限；导出前最多等待 1 秒刷新已排队的事件，日志服务异常不会阻止导出。

## 发布前核对

- 在真实安装包中完成一次“引导 → ACP 连接 → 新建会话 → 发送 → 取消/继续 → 归档/恢复/删除”，并导出 ZIP 检查时间线。
- 覆盖缺少 Agent、缺少 ACP 组件、手动程序路径、Agent 自身未登录/模型不可访问、连接中途退出等情况；核对 UI 的结果和日志结局一致。
- Windows 与 macOS 分别验收原生语音、权限和应用重启。浏览器模拟只验证 UI 接线，不能代替真实设备验收。
- 升级 RC 版本号时运行发布版本一致性检查，具体步骤见[发布检查](RELEASE_CHECKLIST.md)。
