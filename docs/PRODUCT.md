# RambleDesk 产品文档

本文说明当前产品做什么、用户如何使用。产品取舍见[宪章](CONSTITUTION.md)，所有对象名称以[术语表](TERMINOLOGY.md)为准；实现与验收状态分别见[架构](ARCHITECTURE.md)和[质量与待验清单](quality/README.md)。

## 产品定位

RambleDesk 是本地人类反馈工作台。它通过 ACP 托管外部 Agent 会话，也接受外部宿主通过反馈适配器创建请求。人类可以体验产品、回答问题、选择方案或审阅材料，通过专用交互表达判断，并自由书写、说话和附上证据；明确提交后，原宿主取得不可变反馈包继续工作。

RambleDesk 持有反馈与会话协作的事实，不实现 Agent 的推理和工具执行引擎，不管理源码 checkout。请求、草稿和结果的正确性不依赖某次 tool call、连接或窗口一直存活。

## 主要旅程：托管 Agent 会话

1. 打开应用并完成引导：选择资料库位置，按需配置语音、权限、Agent、通知和 Cooking。资料库迁移需保存并重启后继续使用。
2. 从 Agent 目录选择或配置现有后端，选择 Backend Runtime 所在机器上的工作目录。程序检测、ACP 连接成功和真实模型可用分别呈现，不能互相替代。
3. 新建会话先进入草稿 Tab，准备连接并显示后端真实返回的配置选项。准备阶段不发送任务；首条真实用户消息被接受并持久化后，原 Tab 成为正式会话。
4. 在 Agent 页面交互、查看执行过程和回答权限请求。Agent 需要人类回答或判断时，选择反馈工作台类型，通过应用内置反馈命令创建归属于原会话的请求。
5. 在同一会话的反馈页面查看背景和材料，在工作台专用区域作答或批注，在右侧反馈列补充自由说明。正文与结构化交互状态共同自动保存；语音与截图按当前客户端设备能力提供。
6. 完成类型所需回答后提交，或先使用可选 Cooking 整理补充正文再提交。发布保留结构化结果、原始正文、正式正文、附件与哈希；提交失败保留可编辑草稿。没有补充正文的结构化提交不调用 Cooking。
7. 托管 continuation 在原 Agent Session 可接收输入后投递。结果不明时由人类显式处理；“已投递”不等于整个任务完成。取消请求不会自动续接托管 Agent。

一个会话可以处理多个任务和反馈请求。关闭正式会话 Tab 仅关闭视图；停止运行保留历史；删除会话负责停止并清理所属资源。关闭未发送的草稿会清理准备资源。操作与后端支持范围见 [ACP 托管会话](ACP_MANAGED_SESSIONS.md)。

所有 Tab 关闭后显示 Rambelle 空状态和新建会话入口，不自动重新打开会话。新会话在空草稿中提供头脑风暴、系统优化、代码开发三种引导卡片，点击只填入可编辑提示词，由用户发送；提示词要求先做必要问答或小范围了解，尽早发起一次 Ramble 请求确认方向，再展开工作。

桌面端和 Web 端使用同一个应用内项目目录弹窗，可以逐层浏览文件夹、回到主目录或上一级、切换磁盘，也可输入绝对路径跳转。浏览的是 Backend Runtime 所在设备；只有点击确认才切换项目，取消保留原目录和草稿。

## 外部宿主旅程

| 接入 | 请求与等待 | 人类完成后 |
| --- | --- | --- |
| Generic MCP | `request_feedback` 返回持久 `request_id`，Agent 结束当前 turn；没有 blocking wait tool。 | 人类按手动继续提示返回宿主，Agent 调用 `get_feedback`。不承诺自动恢复原上下文。 |
| Pi / dsh 原生适配器 | 通过本地 JSON API 创建请求，在同一个工具调用中等待。 | 终态直接返回原工具调用；中断后按原请求恢复，不创建替代请求。 |

外部请求不要求源码 checkout 路径，宿主会话关联也不是认证凭据。字段、幂等和恢复合同集中在[反馈协议](PROTOCOL.md)，不在本产品文档重复定义。

## 工作台与输入

工作台包含会话导航、请求列表、Ramble / Agent 视图、设置及新会话草稿。正式会话在没有反馈请求时也能显示；请求列表同时呈现待处理与终态请求。用户可以从任务预览跳转到所属会话，不把每个任务拆成新会话。

每种工作台拥有独立的专用区域，右侧反馈列用于补充说明和提交。工作台标题下方统一固定显示「情况说明」，由请求的现状摘要提供，业务内容滚动时仍然可见。Agent 提供的附件在说明下方呈现为可换行的紧凑文件标签，显示类型图标与文件名，点击打开预览；无附件时不留空位。说明与附件共用限高区域，材料较多时在区域内滚动。Ramble 展示体验动作；逐项问答收集一道或多道题的选择或自定义回答，单题关闭自定义回答即可表达方案单选。文稿审阅面向视频脚本、发言稿等材料，保留 Agent 提交的原文，每段复用一条可持续补充的批注，收起后显示一行文字；删除段落显示可恢复的删除线，其余修改通过批注和建议改写表达，由 Agent 在提交后修改原稿。工作台是随应用交付的第一方类型，不是用户安装的插件。

网页评审用于浏览真实开发页面并记录元素意见，终端试用让人类在后端主机的 CLI 中亲自操作并引用输出，拖动排序收集条目优先级、名称修改和删除建议。视觉反馈让人类在固定图片或空白画布上描绘指引；差异评审将意见定位到 diff 的修改前后行和改动块，评审步骤由 Agent 按任务编排。具体接入条件及八种正式类型见[工作台文档](workbench/README.md)。全屏页签由需要宽屏的类型主动提供，同一请求往返保留草稿与运行状态；简单问答和排序使用普通视图，关闭页签不等于停止终端进程。

反馈正文、自定义回答、批注意见和建议措辞的顶部统一提供麦克风、截图、粘贴和附件工具栏，共享同一请求级输入会话。补充说明是默认输入位置；同一输入框的麦克风可开始或暂停录音，点击另一框的麦克风会保持会话并切换后续语音，已经开始的语音仍写回原位置。右侧反馈区域底部只保留左侧 Rambelle 大头像、右侧状态对话气泡，以及有待整理语音时出现的全局整理按钮。桌面悬浮窗呈现同一会话并保留字幕与待处理转写。工作台默认占据更宽的区域，反馈列保持紧凑并可拖动调整。

人类采集的截图、剪贴板图片和文件持久化为反馈附件，归属于当前请求，并保留发起输入框的归属，在对应正文、答案或批注旁引用；它们与 Agent 提供的请求材料分开。打开文件选择器或开始截图后切换字段，不改变本次采集的目的地。剪贴板文字按普通文本进入点击时的输入框，不算语音，也不进入语音整理批次。

Feedback Draft 包括正文与结构化交互状态；正文格式、Action 归属、语音段、附件引用和类型专属状态可恢复。两部分一起保存、一起检查版本、一起提交；Markdown 只投影正文，不能从它反推选项或批注。保存冲突保留本地修改并显示错误，不能以后台刷新静默覆盖人类编辑。正文撤销只作用于正文，工作台中的选择或批注通过相应控件修改。

未知类型、未知版本或不能安全解释的数据进入只读呈现，保留请求材料与已保存草稿，并提示使用支持该合同的客户端。只读原因不改变请求状态；不能把补充正文当成已完成的结构化回答，也不能用直接批准绕过类型合同。显式取消仍按请求生命周期处理。

文字是基础输入。语音可直接写入或先确认，待确认片段可以编辑、整理、丢弃或写入；确认前自动整理默认关闭。Rambelle 状态区有待整理内容时显示“整理 N 段语音”，处理中显示状态，失败后可重试，完成后收起按钮。整理集中处理正文、答案和批注中尚未整理的语音，保留各段的来源标识并原位回填，手动键入和粘贴的文字不进入批次。处理期间切换位置不改变本批次的目标，后来录入的语音留到下一批次，已被修改或删除的片段不会被异步结果覆盖。Auto Tidy 仍可按整个请求的未整理语音段数量触发。Tidy 与提交前的 Cooking 使用独立配置；后者默认关闭，只整理补充说明，不覆盖原始反馈证据，也不代表已整理全部答案和批注。

Desktop Client 提供原生录音、截图、快捷键和桌面壳能力。可选 Web Access 复用工作台和业务合同，通过独立 loopback 服务访问；停止 Web Access 不停止 Agent 或本地集成服务。浏览器文件选择属于客户端设备，不是服务器工作目录选择。

窄视口通过抽屉、滚动区域和布局调整承载同一工作流。尺寸适配不等于手机设备验收，也不意味着提供手机到桌面的 LAN 访问。具体范围见[响应式工作台](WEB_ACCESS_SUPPORT_MATRIX.md)和 [Web Access 支持矩阵](WEB_ACCESS_SUPPORT_MATRIX.md)。

## 不丢失与恢复

- 请求在响应之前持久化；相同 `request_id` 的重试返回同一请求，输入冲突明确失败。
- SQLite 保存包含正文与交互状态的结构化草稿；客户端布局快照不保存第二份正文或答案。已保存内容从后端恢复。
- 浏览器有未保存草稿或保存仍在进行时，通过标准离页确认提示人类；不承诺在卸载时完成异步保存。人类明确离开后，仍可能失去尚未保存的本地修改。
- 发布结果不可变，原稿和正式结果可追溯；发布中断由后端对账，不生成第二份结果。
- 请求终态、反馈包发布和 Agent 续接分别表达。允许直接批准的最终总结可以完成请求而不发布反馈包；它不能替代需要详细意见的反馈请求。
- 断线、重启、权限拒绝或模型服务失败都有可见状态；连接成功不冒充反馈闭环已完成。

## 非目标与判断标准

当前不提供自有 Agent 推理/工具执行引擎、源码 checkout 管理、动态工作台插件或市场、任意 Agent 生成 UI、云同步、账号与团队权限、完整移动端 App、LAN/TLS Web 服务、独立 Web 部署、通用系统听写或多阶段 Agent 编排。现有 CLI 诊断入口不扩大这些产品承诺。

产品改进优先看：真实体验闭环是否完成、请求与草稿是否可恢复、反馈能否回到原会话、失败是否清楚可处理，以及人类记录和提交是否顺畅。自动化、特定构建的真实操作和仍未验证的平台分别登记在[质量与待验清单](quality/README.md)，不以版本标题宣称全部完成。
