# 工作台实现状态与维护边界

更新日期：2026-10-02。本文记录当前源码范围与后续扩展边界，新增工作台尚未包含在已发布的 0.4.0 安装包中；具体字段、所有权和交互分别由[反馈协议](PROTOCOL.md)、[架构](ARCHITECTURE.md)及[工作台文档](workbench/README.md)维护，不在这里重复定义。实现存在不代表所有设备或宿主已经完成人工验收。

## 当前实现

| 能力 | 当前范围 | 详细入口 |
| --- | --- | --- |
| 第一方类型 | 八种正式类型：`ramble`、`questions`、`document_review`、`web_review`、`terminal`、`sort`、`visual_feedback`、`diff_review`，使用独立视图与静态注册。新单选场景使用单题问答。旧单选与开发评分不计入正式数量。 | [协议](PROTOCOL.md)、[ADR 008](adr/008-typed-human-feedback-workbenches.md) |
| 工作区布局 | 工作台占较宽主列；情况说明和请求材料固定在顶部限高区域，业务内容独立滚动。紧凑反馈列承载补充说明、保存状态和统一提交，可拖动并保存列宽。 | [架构](ARCHITECTURE.md) |
| 全屏选配 | 类型主动声明 `layout.expanded` 才提供入口；普通模板、简单问答与排序默认关闭。启用后普通/全屏页签共用请求、草稿及运行状态，左侧会话导航保持可用。 | [新增教程](workbench/adding-a-workbench.md) |
| 草稿与结果 | 正文和类型状态同 revision/CAS 保存，服务端验证同一个冻结快照后发布不可变反馈包。 | [协议](PROTOCOL.md) |
| 共享输入 | 正文、自定义回答、批注意见和建议措辞共用 TipTap 基础与请求级语音、剪贴板、截图、附件能力。每个字段有工具栏，附件跟随发起字段。 | [共享输入](workbench/shared-input.md) |
| 全局语音整理 | Rambelle 状态区显示头像、气泡及有待整理语音时的按钮；一次整理本请求各字段的语音并回填原处。 | [共享输入](workbench/shared-input.md) |
| 文稿审阅 | 只读原稿、单段文字锚点、每段可续写批注、建议改写、可恢复删除线、显式整稿判断。 | [文稿审阅](workbench/document-review.md) |
| 网页评审 | 真实网页浏览／元素选择、底部固定浮动批注、编号与集中回看，保留 URL、视口及元素信息；开发页通过桥接脚本接入。默认普通工作台，网页工具栏“选择元素”旁的全屏评审按钮打开独立页签；页签往返共用草稿和网页状态。浮动卡只显示批注编号、意见和输入工具，捕获信息保留在数据与终态历史中；设备按钮只显示图标与 tooltip，固定手机画布居中。 | [网页评审](workbench/web-review.md) |
| 终端试用 | 请求绑定真实 PTY，从体验 Markdown 复制命令，输出引用到正文、转录及 TUI 画面随反馈保存；新页签继续同一会话，停止/退出后可主动重开并保留各轮记录，提交前统一收尾。 | [终端试用](workbench/terminal.md) |
| 拖动排序 | 条目排序、名称编辑、删除与恢复；草稿保留未完成名称，提交返回最终名称、顺序与删除 ID，终态只读。 | [排序体验](../playground/workbenches/materials/sort.md) |
| 视觉反馈 | 以固定图片或空白画布为背景，绘制简笔、箭头、矩形及文字；提交保存合成 PNG 与结构化标注，历史按同一来源回看。 | [视觉反馈](workbench/visual-feedback.md) |
| 差异评审 | 查看固定 diff、切换文件，对修改前后行、行范围及改动块批注；提交批注与整体意见，具体流程由 Agent 编排。 | [差异评审](workbench/diff-review.md) |
| 类型发现 | `list_workbenches` / `describe_workbench` 提供用途目录与按需 schema；MCP、Generic JSON 和托管命令复用同一合同。 | [协议](PROTOCOL.md)、[ACP 指南](ACP_MANAGED_SESSIONS.md) |
| 普通类型扩展 | Rust 与前端各有一个静态注册入口；类型拥有合同、规则、字段、视图与示例。脚手架生成业务模块和测试材料，宿主统一草稿、输入和生命周期；测试评分类型验证扩展链路。 | [新增教程](workbench/adding-a-workbench.md)、[框架验收](workbench/framework-validation.md) |
| 首次引导 | 自由反馈、文稿审阅、网页评审和终端试用提供 Rambelle 聚光步骤，业务视图就绪后按类型和引导版本在客户端记录，可跳过或重看。简单问答和排序不增加引导。 | [首次引导](workbench/onboarding.md) |

用户启用／禁用类型、跨客户端引导同步尚未实现，不属于已有发现工具或本地首次引导的隐含能力。Pi / dsh 原生适配器的工具参数仍保留 Ramble 入口；其余类型使用协议列出的入口。

## 维护与扩展

新增类型必须先有真实交互和明确的输入、草稿、结果合同，再通过静态注册组合视图。沿用公共情况说明、反馈列、保存队列、输入准备和发布链路；类型视图不导入 transport、设备采集或宿主协议。新字段接入明确的 `InputTarget`，不根据任意 DOM 焦点猜测写入位置。

创建请求时拒绝未知合同；读取已有未知类型或版本时只读保留，禁止覆盖保存、提交或直接批准，显式取消仍是请求级操作。没有类型的旧请求继续使用 Ramble 及原幂等身份。

旧 `single_choice` 输入、草稿和结果，旧审阅草稿中的多条批注与 `keep` / `revise` 标记，以及旧语音回执仍需保留兼容；批注旧 `status` 字段读取时忽略，意见保留。新界面的简化不构成删除旧数据的理由。降级到更早应用版本的限制见[数据兼容](DATA_COMPATIBILITY.md)。

语音 Tidy 可以跨字段整理已记录来源的语音段；提交前 Cooking 只处理补充正文。两者都不能自动更改固定选项、整稿判断或原稿，也不能覆盖等待期间的人类修改。新增变换必须保留不参与变换的结构化字段与元数据。

如将来允许禁用类型，需要先定义设置作用域和恢复语义；禁用应限制新请求选择，不能使已有草稿和结果失去解释方式。进一步的工作台场景由实际需求驱动；动态插件市场、任意 UI schema、通用工作流引擎、跨版本文稿锚点迁移和视频时间轴均未纳入当前实现。

## 验收边界

工作台数量和页面预览不能代替完整反馈闭环。修改后根据影响范围检查：

- 类型的创建验证、保存、恢复、完整性、无补充正文提交、取消和已发布结果读取。
- 正文与类型状态并发修改、revision 冲突、切换请求和后台写入，不能丢失其中一部分。
- 未知合同只读保留；兼容读取不清空旧答案、批注、标记或附件引用。
- 输入框切换只影响后续语音；已开始的语音、剪贴板、截图与文件选择保留原目标，失败内容不会改挂正文。
- 整理回填保留原字段，跳过已被人类改动或删除的片段，普通键入和粘贴不进入语音批次。
- 文稿审阅验证中文和 emoji 锚点、拒绝无效引用、续写同一批注、删除确认、收起摘要、恢复删除线及显式整稿判断。
- 网页验证 bridge 来源/会话、元素定位、视口与普通/全屏共用页面状态；终端验证重连、多轮重开、最终输出与提交前真实资源收尾；排序验证编辑、删除/恢复、顺序与只读结果。
- 普通类型扩展只修改两份共享注册文件；开发评分受前后端开发开关限制，生产目录和视图不包含它。全屏关闭的类型不显示入口。
- 首次引导的跳过、重看、锁定和请求切换不修改草稿，也不自动触发业务操作。

组件及领域测试用于验证状态边界；`workbenches.html` 用于浏览器交互预览，语音模式模拟识别和整理；[Playground](../playground/workbenches/README.md)用于真实 Agent、持久化和提交验收。麦克风、原生浮窗、截图和设备权限需要单独在相应平台验证，不能由模拟输入结果推断可用。

设计取舍保存在 [ADR 008](adr/008-typed-human-feedback-workbenches.md)；早期接口提案和实验步骤从 Git 历史追溯。当前文档不保留已完成阶段的待办清单，避免把过期顺序误当作下一轮实施要求。
