# ACP 通用接口收口

本轮在 `codex/acp-managed-sessions` 原工作区完成，保留已有未提交工作，没有提交或推送。

## 最终边界

- `rambledesk-core` 定义应用自己的 Driver、Connection、配置与交互契约；生产调用不依赖 ACP SDK 类型。
- 配置统一为 `SessionConfiguration.options`，修改统一为 `{config_id, value}`。ACP 内部处理标准选项、新旧模式/模型协议及私有元数据，并保存原始调用路由。前端仅渲染配置项。
- 配置 ID 是当前连接内稳定的 UUID 句柄。选项暂时消失后恢复沿用原句柄；重连后旧句柄无法命中新连接的选项。标准类别优先级保留原有空格/大小写兼容。
- 待处理事项统一为 `SessionInteraction`，明确区分 `permission`、`question`、`plan`；响应类型必须匹配。快照字段为 `interactions`，状态为 `waiting_input`，应用入口为 `respondManagedInteraction`。
- Form、Grok、Cursor 模块分别负责协议解析、回复、取消和方法注册。公共输入层负责表单校验、会话归属和等待请求生命周期，不根据品牌分配行为。
- 低层 SDK 接口集中在 `rambledesk_acp::probe`，crate 根提供高层 Driver；原有 SDK 通过 probe 供示例与协议测试使用。

## 生命周期修正

- 回答必须属于原连接和原轮次。迟到回复不能移除新连接或新轮次中复用相同 ID 的卡片；原轮次已经正常结束时，回答仍返回成功。
- 轮次最终收尾会按请求类型取消残留待处理事项。清除卡片时同步释放对应请求，并通过轮次锁避免下一轮抢先复用请求 ID。
- 回答类型不匹配、选项无效、表单校验失败均不消费待处理请求；保留重试、取消和跨会话隔离。

## 保留的范围

数据库格式、持久化会话身份和历史不变。运行时应用契约随前后端一起更新；本开发分支的旧前端应随新后端重新加载。

表单仍使用已限定的通用平面 JSON Schema 子集；复杂约束保持可见但不允许弱化后接受。未新增厂商账号实测，协议兼容证据仍以本地源格式 fixture 与此前调研为界。安装探测和 Ramble 工作流注入继续作为此集成模块内独立职责，没有引入新 crate 或运行时插件系统。
