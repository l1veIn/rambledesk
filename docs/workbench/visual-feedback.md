# 视觉反馈工作台

`visual_feedback` v1 用于在图片或空白画布上表达空间意见，例如圈出问题、画布局方向或给 Agent 简单视觉指引。原背景保持不变，简笔、箭头、矩形、文字及各标注的意见存入草稿；整体说明使用共享反馈正文。

## 创建请求

Agent 先通过 `describe_workbench` 读取当前 schema。输入包含 `title`、`source_version`、`width`、`height`、可选 `background_color` 和 `image_file_name`。

- 空白画布使用 `image_file_name: null`，指定 32–4096 的整数宽高；底色为 `#RRGGBB`，默认白色。
- 图片背景将 PNG、JPEG、GIF 或 WebP 作为普通请求附件发送，`image_file_name` 精确匹配保存后的附件文件名。同名图片必须唯一，按 EXIF 方向校正后的原图显示尺寸必须等于画布尺寸。文件在创建请求时复制并按内容哈希保存，后续不读取 Agent 原路径。
- 底色显示在图片透明区域下。图像解码有尺寸及内存预算，不能仅以扩展名或 MIME 判定有效。
- 合成 PNG 遵循反馈附件的 20 MiB 上限。压缩源图符合附件上限并不保证合成 PNG 合格；大照片应在创建请求前缩小，并以缩小后的实际尺寸创建画布。超限时保留草稿并提示用较小图片或画布重新创建请求，不在提交时自动缩放原图或标注。

```json
{
  "type": "visual_feedback", "version": 1,
  "data": {
    "title": "画出你希望的布局", "source_version": "layout-v1",
    "width": 800, "height": 500,
    "background_color": "#fff8ed", "image_file_name": null
  }
}
```

请求身份、情况说明和附件规则仍见[反馈协议](../PROTOCOL.md)。

## 编辑与保存

首次进入可编辑视觉反馈工作台时，会显示五步使用引导，依次介绍绘图工具与撤销、背景画布、缩放与全屏、标注列表与意见，以及统一提交。空白画布和图片批注共用按类型记录的首次状态；完成或跳过后不再自动重复，标题旁的使用引导（Show guide）按钮可以重看。引导只介绍真实控件，不绘制标注或生成附件。公共行为见[首次使用引导](onboarding.md)。

工具提供自由笔、箭头、矩形和文字，支持颜色、线宽、选择标注、删除、撤销／重做、缩放及按需全屏。坐标使用原画布的整数像素，缩放只改变显示；切换视图不改变标注位置。

每条标注有稳定 `id`、`kind`、`points`、`color`、`stroke_width`、`text` 和 `body`。文字和意见接入共享输入字段，可使用请求级语音、附件和整理；空文字可保存为未完成草稿，发布时文字标注必须有内容。其他图形的 `text` 为空，箭头和矩形要求非零几何。

最多 500 条标注、总计 20000 个点；单笔自由线 2–2048 点，箭头／矩形两点，文字一点。正文长度、形状、字段及其他限制以当前 schema 和校验为准。

## 提交与回看

提交准备从固定背景和当前标注生成 PNG。宿主先保存草稿，经既有附件队列上传并回灌新 revision，再将 `composite_attachment_id` 写入状态；统一发布流程保存这个状态并验证附件属于当前请求、媒体类型、内容哈希和实际尺寸。生成失败保持可编辑草稿，重试不会将意见转移到其他请求。

修改标注会清除旧合成引用，下次提交重新生成。删除合成附件后也会清除引用并允许重生成。生成附件本身不构成人类输入，需要绘制／文字标注或共享正文。只有整体说明时仍生成当前画布的 PNG。

结果位于 `manifest.workbench.result`，包含 `source_version`、`width`、`height`、`annotations` 和 `composite_attachment_id`。该 ID 指向反馈包的 PNG 附件，Agent 同时读取图片与结构化意见。终态使用同一来源和标注只读回看。

体验材料见[空白画布／图片批注](../../playground/workbenches/materials/visual-feedback.md)；预览和自动测试不代替真实设备输入验收。
