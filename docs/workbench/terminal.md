# 终端试用工作台

`terminal` v1 让用户在请求绑定的真实终端中亲自试用 CLI。Agent 提供试用目标、起始目录、可选 shell 和建议命令；工作台保留终端上下文，输出片段可引用到右侧反馈正文。字段及限制以 `describe_workbench` 返回的 schema 为准。

## 使用流程

默认显示普通工作台，左侧会话列表保持可用。用户点击开始试用后，Backend Runtime 在请求给出的目录启动 shell。建议命令按钮只填入文本，用户按回车执行；用户也可以修改或自由输入。方向键、Ctrl+C、交互提示与 ANSI 屏幕重绘由 PTY 和 xterm 处理。

选中输出后，工具栏的引用按钮将片段追加到右侧富文本正文，用户继续写意见。转录不自动灌入正文。正文继续使用既有语音、截图、粘贴、附件和草稿链路。

终端工具栏提供全屏入口，在新的工作区页签继续同一请求。普通/全屏页签切换保留同一终端视图；切到其他请求只断开视图轮询，后台进程继续存在，返回时重连。关页签不代表停止进程；停止按钮明确结束会话。正常停止或 shell 退出后，本版不提供在该请求内重新启动；用户可以继续引用输出、编辑反馈，重新试用则创建新请求。

## 记录与提交

草稿中的 TerminalState 保存会话起始 cwd/shell、cols/rows、原始 ANSI 转录、用户最后看见的屏幕、会话状态及 shell 退出码。原始按键不持久化，不推测任意 CLI 的逐条命令执行边界或退出码；一般 shell 的命令回显出现在转录中。

转录有容量上限，超出后保留尾部并标明 truncated。最新屏幕用于查看交互式 CLI 当时呈现的内容；它和原始转录一起提供上下文。它不是完整操作录像。正文意见或输出引用才构成人类反馈，欢迎横幅与空闲提示符不自动成为用户意见。

提交前停止终端、等待最后输出、更新结构化状态，再走既有草稿保存与提交。停止/读取失败时保留草稿并阻止提交，可重试。完成/取消后禁止新的运行输入；已提交反馈冻结为不可变结果，可以只读查看。进程属于运行时，应用重启后保留已保存记录，旧进程不会自动复活。

## 运行边界与验证

Desktop 与 Web Access 经同一 Application Transport 合同连接 Backend Runtime 的终端。CLI 运行在后端主机，并显示起始目录；浏览器终端不执行浏览器所在设备上的命令。命令输入不会被录制为独立按键日志。现有 Web Access 的身份校验与 loopback 边界继续适用。

`/?preview=fixtures&workspace=terminal` 是明确标注的内存交互样例，不执行本机进程。真实 CLI 人工用例见 playground 的 `06-terminal.json` 和 `materials/terminal-demo.mjs`，无需安装依赖。模板 cwd 在 prepare 时解析为 playground 绝对目录，不能直接发送未准备的模板。

2026-09-30 在 Windows 10.0.26200.9457、Chromium 151.0.7922.34 / Playwright 1.62.1，使用隔离 Web Access、真实 ConPTY 和固定 CLI 完成帮助、问候、方向键菜单、Ctrl+C、错误提示、鼠标选中引用、普通/全屏页签往返、实际 UI 提交及刷新后只读查看。两种模式都保留左侧会话列表，普通/全屏复用同一终端；提交顺序为 stop → 最终 save → submit，冻结 manifest 与草稿会话逐字段一致，浏览器和 HTTP 错误均为 0。

真实 PTY 回归覆盖 resize、重连、正常退出的末尾大输出、无前端应答时立即 stop/drop、失败启动清理及 Windows 后代进程清理。前端控制器和 App 回归覆盖所有提交入口、准备期间切换/取消保护、停止失败重试、永久会话丢失保留记录及临时网络故障。Linux target 的 core 编译检查通过；它不证明 Unix 真实 PTY 或目标设备兼容。

macOS/Linux 和真实手机尚未实际验收。Unix 目前按 PTY 前台进程组及 shell 清理，独立后台进程组的完整回收仍需补齐并在目标平台验证；不要据 Windows Job Object 的测试宣称所有 Unix 后台任务都能清理。任意第三方 CLI 的交互行为需要分别验收。
