# 工作台重构：来龙去脉（总览）

状态：**总览文档**。它讲清"为什么做、已经做了什么、结论是什么、接下来做什么、去哪儿看细节"。
术语以[术语表](../TERMINOLOGY.md)为准；阶段与验收以[工作台演进路线](../WORKBENCH_EVOLUTION.md)为准；
协议字段以[反馈协议](../PROTOCOL.md)与 `crates/rambledesk-core/src/feedback/model.rs` 为准。本文不另立真源，只把它们串成一个故事。

## 0. 一句话

RambleDesk 现在是一个**固定形状的反馈界面**；目标是从"一种固定界面"演进到"可以注册多种工作台"，
让 Agent 能按任务选择人机交互的形式，而**反馈协议、草稿、提交与续接机制保持不变**。

## 1. 起点：一个固定形状的闭环

- **产品**：本地 human-feedback workbench。Agent 发起反馈请求 → 人在界面里填写 → Agent 读取反馈包继续工作。
- **协议**：只有一套形状——`what_happened`（≤200 字摘要）+ `actions`（1–20 条可体验动作）+ 材料附件 + 自由正文。
  也就是说：**协议形状本身就是"默认工作台"的形状**，只是协议里没有"工作台"这个词。
- **界面**：中间一块"工作台"，右侧一条 `CommandRail`（提交 / 取消 / 附件）；编辑器、附件、交付散在几处。
- **具体痛点**（这一轮重构的真实触发点）：
  1. 输入分散：工具栏图标与文字挤在一行展不开；
  2. 附件块占据整块版面，而附件其实已经内联在正文里；
  3. "全屏任务简报"是第二套实现，自带提交按钮与旧样式变量；
  4. 布局没有宽度预算，窗口最小尺寸与内容需求脱节。

## 2. 阶段 0/1：先把"输入面"做对（已完成）

- **阶段 0**：输入集中到 TipTap——语音、截图、剪贴板、文件、Tidy 都写进同一份文档（`1f86ea9`、`3affba8`）。
- **阶段 1**：反馈列右移成独立一栏（`e35ddde`、`e6eeff1`、`34ea6fe`）：
  - 宽度按像素策略：默认 700、可拖 560–900、任务简报保底 420，换算成 PaneForge 的百分比；
  - 窄屏（<1180px）上下堆叠，且**不重建编辑器**（不丢选区与未保存内容）；
  - ACP/Agent 状态归到反馈列顶部；附件改为页脚"字符数 + 附件数"入口；Rambelle 状态压成底部一条；
  - 悬浮窗增加提交按钮；窗口默认与最小尺寸 1600×900。
- **结果**：一屏之内"左看任务、右写反馈"，编辑器与提交只有一份实现。

## 3. 阶段 2：容器与工作台分离（第一刀已完成）

**为什么**：要支持多种工作台，就不能让"中间那一栏"既当容器又当某种交互，
也不能让工作台拿 60 多个 prop 直接操作编辑器、采集与提交。

**做了什么**（`cd76c53`）：

- `WorkbenchContainer`：面板外壳与加载态、分栏与宽度策略、通用反馈列、提交协调、附件预览、粘贴订阅；
- `RambleWorkbench`：请求身份行、任务简报、体验动作、动作选择；
- `SessionWorkbench` 变成两者的组合，**对外 prop 与导出的编辑句柄不变**（App 与既有测试零改动）。

**顺手收敛**（`5dcc8ea`）：隐藏全屏简报视图的入口（`⧉` 按钮、自动打开、设置开关），
它是第二套实现；视图与组件代码保留，恢复 = 删掉几处 `{#if false}`。

**这一刀让我们看清的三件事**（后面所有设计都建立在这里）：

1. "工作台"这个词当时**同时**指产品、容器和交互类型——术语缺位（已在 `3e219bc` 补上容器与反馈列）；
2. "当前写到哪里"**没有唯一主人**：散在 `activeActionByRequest`、文档里的 `Action Group` 锚点、以及每个采集调用点的即时查询；
3. 协议形状 = 默认工作台的形状，所以"多工作台"这件事本质是**要不要把隐含形状显式化**。

## 4. 结论与设计主张（地基）

1. **工作台是数据，不是工具**：Agent 侧工具面恒定，新工作台 = 新类型 + 新 `inputSchema`，而不是新工具。
2. **共享材料 vs 类型专属字段**：`title` / `what_happened` / `context_refs` / `attachments` / `source_hint` 属于框架；
   Ramble 的 `actions` 用注册项 `ownedFields` 声明归属，**先不迁移、不改幂等哈希**。
3. **一个客户端一个可编辑反馈列**：工作台不复制编辑器、采集管线、草稿或提交实现。
4. **输入目标应当显式化**：工作台声明目标、容器持有目标、采集显式携带目标，文档锚点只是投影。
5. **创建时拒绝 vs 渲染时降级是两件事**：服务端在创建时校验类型与数据；客户端在渲染时降级为"材料 + 自由反馈"。
6. **版本分三种**：工作台类型版本、专用数据版本、首次引导版本，不合成一种。
7. **明确不做**（反模式）：给每个工作台复制基础设施；把 UI 变成协议；用工具数量表达类型；
   把 Markdown 当结构真源；为抽象提前造 SDK / 动态加载；在没有第二个真实工作台之前冻结接口。
