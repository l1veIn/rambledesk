# 工作台框架重构与新增体验目标

- 分支：`codex/workbench-framework`
- 日期：2026-09-30
- 状态：设计与验收目标，尚未实现
- 现有实现：[工作台实现状态](../WORKBENCH_EVOLUTION.md)
- 当前合同与所有权：[ADR 008](../adr/008-typed-human-feedback-workbenches.md)、[架构](../ARCHITECTURE.md)

本分支将现有共享基础整理成稳定的第一方扩展接口。成功标准是新开发者能在自己的业务模块内完成普通工作台，公共布局、草稿、输入与提交编排不再随类型增加分支。已有工作台作为迁移对象，输入、草稿、结果与历史兼容保持明确。

## 1. 普通工作台包含什么

普通工作台使用请求材料和结构化状态表达业务，复用宿主的反馈正文、草稿保存、语音、附件和发布。典型场景包括选择、评分、排序、批注，以及带意见框的业务表单。业务界面可以有自己的布局和交互。

普通工作台无需新增后端进程、浏览器桥接、持续流连接、设备能力、Application Transport command 或持久化设施。有这些需求的类型还需要运行资源适配器及相应传输验证。复用已有宿主能力不算新增运行资源。

带业务文本字段仍属于普通工作台。开发者需要在本类型模块中声明字段适配器，描述稳定身份、读取与替换、长度和失效条件；共享框架据此提供语音、粘贴、附件引用和整理回填。仅渲染一个 `WorkbenchTextField` 不足以接通这些能力。

## 2. 新增体验有多简单

目标流程固定为四步：生成模板、填写业务合同和规则、编写业务视图、运行共同验收。

计划提供以下脚手架命令；当前尚不存在，不能当作现有开发命令执行：

```sh
pnpm workbench:new rating_review
```

脚手架在接口稳定后实现，负责创建模块、示例、体验 Markdown 和测试入口，并补入两个静态注册项。它生成可运行的最小示例，开发者随后修改业务内容；类型身份、完成条件和版本兼容仍由开发者决定。

以最小“评分＋意见框”工作台为例，业务代码目标分为三份：

| 文件角色 | 开发者负责 | 框架负责 |
| --- | --- | --- |
| Rust 类型模块 | Data / State / Result、输入与草稿校验、发布条件、结果投影、类型说明和示例 | schema、DTO 导出、目录组合和公共提交策略调用 |
| 前端 definition 模块 | 输入识别、状态解码、完成提示、布局声明、意见字段适配器和视图绑定 | 注册查找、公共能力注入、输入路由与生命周期调用 |
| Svelte 业务视图 | 展示评分、意见框和本类型交互，通过宿主接口更新状态 | 公共情况说明、请求材料、反馈列、保存状态、提交和全屏页签 |

另外需要本类型的示例、体验 Markdown 和业务测试。脚手架生成基本文件，共同测试检查框架合同，开发者补充评分范围等业务断言。复杂业务可在自己的模块内拆分更多文件，文件数量不是限制。

最重要的可量化约束是：**新增普通类型时，修改的共享生产文件最多两个，分别是 Rust 和前端的静态注册入口。** 脚手架可完成这两处登记。按实际变更文件计数，不以“两次插入”掩盖对多个文件的修改；生成文件和本类型的业务、测试、材料文件不计入。模块声明、强类型联合、导出类型清单等机械组合应从同一后端注册声明产生，不能另设多个手工维护入口。

生成的 TypeScript 合同与 schema 可以变化，但不手工编辑；预览与 playground 按统一示例约定接入，不能再要求开发者修改第三、第四份类型分发表。

## 3. 开发者直接复用的能力

| 能力 | 接入方式与边界 |
| --- | --- |
| 公共布局和请求材料 | 宿主统一显示；类型声明自身业务区域的布局需求 |
| 草稿、恢复和保存状态 | 类型通过宿主更新 Interaction State，正文与状态同 revision/CAS 保存 |
| 提交、取消和历史 | 宿主调用类型的规则与可选准备接口；服务端校验最终结果，历史沿用本类型视图的只读模式 |
| 引用到反馈正文 | 类型调用宿主的引用接口，不直接操作正文 Editor |
| 全屏页签 | 类型声明支持并调用宿主入口，左侧会话列表由宿主管理 |
| 业务字段的语音和附件 | 类型提供字段适配器，共用请求级采集、回执和写回链路；具体设备能力按客户端可用性提供 |
| 类型发现和示例 | 后端注册项提供说明/schema/example；复用现有发现工具与统一预览、playground 约定 |

新增普通工作台无需理解保存队列、语音设备、HTTP/Tauri 或发布事务的内部实现，仍需编写 Rust 业务规则与 Svelte/TypeScript 页面。

## 4. 新增普通类型不能触及的公共代码

验收新增类型时，以下公共生产模块不得因该类型增加业务分支：

- `App.svelte`、`RegisteredWorkbench.svelte`、`SessionWorkbench.svelte` 和公共工作台容器。
- `publisherController.ts`、`submissionController.ts`、草稿保存队列与数据库实现。
- HTTP/Tauri 路由、Application Transport command 和 MCP 工具定义。
- `domain/inputTarget.ts`、`workbenchFields.ts`、语音与附件写回实现。
- 中央输入验证、状态解码、完成条件和结果生成的逐类型逻辑。

这些公共模块可以在本次框架迁移中修改。框架完成后的扩展演练只能添加类型自己的模块、两个注册项及本类型用例；若还需要修改上述公共流程，本分支的新增体验目标就未达成。

## 5. 接口和所有权

服务端类型定义负责合同、版本、校验、结果和发现元数据；前端类型定义负责呈现、可编辑状态与能力声明。二者通过生成合同连接，最终业务裁决留在后端。Rust 保留强类型数据，不为减少文件改动把所有业务值改成任意 JSON。

宿主负责导航、公共材料与反馈列、草稿队列、输入协调及提交编排。业务视图通过宿主接口交互，不自行持有另一份正文、保存队列、录音会话或发布状态。

字段适配器负责本类型字段的身份解码、身份比较、读取与替换、验证和失效检查。异步操作固定开始时的请求与字段；字段被删、不可编辑或来源版本不匹配时报告失败，不改写其他字段或正文。旧问题、文稿和网页目标及其输入回执保留原有兼容解释方式。

需要运行资源的工作台提供可选控制器或适配器。视图挂载/卸载与请求、草稿、后端资源的生命周期分别管理。终端的重连、停止、多轮记录归并和提交前 drain 由同一控制路径处理，挂载与未挂载提交入口不得各写一套业务。

可保存的草稿与可发布的结果有不同条件。前端负责准备和提示，后端负责请求归属、版本、CAS 和发布条件；未完成资源收尾的记录不能仅凭前端按钮状态被发布。运行资源的完成依据来自 Backend Runtime 的请求归属与实际资源状态，不能把客户端草稿中的 `stopped` 当作资源已结束的证明；资源丢失和旧记录恢复按明确兼容规则处理。

## 6. 实施顺序

1. 完成本设计稿与新增体验验收标准，建立现有合同、兼容输入和关键行为的回归基线。
2. 收拢后端类型定义与静态声明，继续生成合同；以 questions 验证前端定义和注册接口。
3. 提取字段适配接口，迁移共享输入目标和写回的类型逻辑，保留旧记录兼容。
4. 提取宿主能力和可选生命周期接口，迁移文稿、网页，再迁移终端；统一所有提交入口。
5. 接入统一示例发现，完成脚手架与新手教程，进行独立的普通工作台扩展演练。

每步独立提交，用现有类型验证接口后再扩展。第一方类型随应用构建；本轮不建立远程插件加载、UI DSL 或插件市场。

## 7. 分支完成的证明

使用一个仅供测试的“评分＋意见框”工作台进行演练，不增加新的生产产品类型。该类型只在测试/开发构建中注册，使用这个构建的真实后端经正常目录、请求、保存与发布入口运行；正式构建不包含此类型，模拟预览不能代替闭环验收。输入包含评审材料；草稿包含可未选择的评分和意见；结果要求合法评分，意见为可选文本。它必须同时证明结构化选择与新业务文本字段的接入。

验收人员按教程新增该类型，记录完整 diff、手工修改入口和运行命令，检查：

- 模板可以启动预览，通过现有发现/请求入口创建实例，业务修改只在本类型模块内发生。
- 评分与意见能保存、恢复，与反馈正文并发修改时不丢字段；未完成评分不能靠填写正文绕过。
- 意见框能接入共享语音、粘贴、附件和整理；等待期间目标被删除或失效，输入不能落到正文或其他目标。
- 普通与全屏视图共享同一请求和草稿，左侧会话列表保持可用。
- 工作台、任务页签与其他提交入口执行一致的准备、保存和发布；取消和只读历史有明确行为。
- 未知类型/版本只读保留，旧类型合同与幂等身份不变；所有必需注册关系有一致性检查。
- diff 满足最多两个共享生产注册入口的约束，生成合同通过检查，预览和 playground 不另加中央类型分支。

与此同时，已有工作台通过按影响范围选择的回归与 playground 验收。终端特别检查停止/退出后重开、丢失恢复、多轮容量与最终输出；麦克风、截图和跨平台能力按实际设备记录，不以模拟结果宣称验证完成。

教程、脚手架及演练结果共同证明新增体验。不能只依据目录重新整理或 `if/else` 数量减少宣布框架完成。
