# 请求级共享输入

正文和工作台业务字段保留各自的语义，共享 TipTap 编辑基础、语音、字幕、悬浮工具台、剪贴板、截图和附件能力。批注与自定义回答仍按普通字符串保存，原稿仍只读；字段的数据合同与输入框使用的编辑技术是两件事。

## 每个输入框一条工具栏，共享一个会话

反馈正文、自定义回答、批注意见和建议措辞的顶部都有相同的输入工具栏：麦克风、截图、粘贴、附件。工具栏负责选择本次输入的位置，录音器、字幕队列和采集能力仍由请求级会话拥有。工作台默认占据更宽的区域，反馈列保持紧凑并可拖动调整；桌面悬浮窗呈现同一个输入会话。

这些输入区复用 `TiptapInput` 的挂载、销毁、可编辑状态和公共呈现。反馈正文保留富文本节点；`WorkbenchTextField` 把普通字符串投影为轻量 TipTap 文档，并把编辑结果写回原业务字段。自定义回答和批注中的语音也在原位置显示小麦克风标识，标识属于展示装饰，不进入复制文本或提交结果。每个可见字段有自己的选区与撤销历史；切换到另一题会创建该题的编辑视图，不把上一题的撤销历史带过去。

新请求的默认输入位置是补充说明。点击输入框的麦克风选中字段并开始或继续现有会话；正在录音时再次点击当前输入框的麦克风会暂停，点击另一输入框的麦克风则保持录音并切换后续语音的落点。键入或聚焦字段只改变下一段位置，不会自动开启录音。隐藏或收起字段不销毁会话。

右侧反馈区域底部保留唯一的 Rambelle 状态区：左侧是放大的人物头像，右侧是简短状态对话气泡。有待整理语音时显示“整理 N 段语音”按钮，处理中和失败信息也由这一区域呈现；没有待整理内容时收起按钮。录音启动、暂停和输入位置切换都由各输入框顶部的麦克风完成，这一区域不再显示字幕、位置文字、定位或默认输入等辅助控件。

已开始的语音、剪贴板导入和整理任务各自固定目标。切换位置只影响后续输入，不重新分配正在进行的操作。失效字段保留明确错误和待处理内容，不能因为补充说明是默认位置而把失败内容转移过去。

## 所有权与目标

- 一个客户端的请求输入会话拥有一个麦克风控制器和一条待确认语音队列。工作台输入组件通过 `VoiceInputContext` 选择目标或启动、暂停录音，不创建独立录音器。
- 同一客户端保持一个反馈正文所有者和一份完整草稿。可见的正文、回答和批注通过同一编辑组件编辑各自字段；隐藏字段不保留 Editor，后台写入使用草稿变换，不依赖界面 Editor 存活。
- `InputTarget` 固定请求身份，`destination` 明确表示正文及其 Action、指定问题 ID 的自定义回答，或者指定来源版本、批注 ID 和 `body` / `replacement` 字段。
- 焦点和麦克风按钮选择**下一段**目标；焦点本身不启动录音。已有录音时选择另一个字段继续使用同一麦克风。
- `speech-started` 固定当前段目标。后续目标切换不重定向该段；乱序或迟到的稳定结果仍按原段身份写入。桌面悬浮窗中的字幕仍保留当前段、下一段及待确认内容的目标信息。
- 意见和建议措辞使用不同目标。目标字段被删除、来源版本改变、请求关闭或客户端不认识目标时，写入失败并保留待处理转写，不能偷偷写入正文。

`SpeechTarget` 是语音侧对该目标合同的别名；普通粘贴、截图和附件直接使用 `InputTarget`，字段有效性统一由 `workbenchFields` 校验。

当前接入点是反馈正文、问答自定义回答、文稿批注意见和建议措辞。新字段需要显式注册领域目标，不能根据任意 DOM 焦点猜测。

问答只有 `allowOther:true` 且人类明确选择自定义回答时才能接收文字或语音。语音按问题 ID 追加 `value`，同步 `label`，不自动跳题；切到另一题、正文或批注不改变已开始的语音段。改选固定选项或使用“清除回答”删除记录后，迟到转写保留待处理，不重建自定义答案或覆盖选择。把自定义输入框内容删为空仍表示正在编辑自定义回答，可继续口述。

## 整理未处理语音

Rambelle 状态区统一提供“整理 N 段语音”，统计本请求在补充说明、自定义回答、批注意见和建议措辞中的未整理语音段。各字段保留语音来源标识，键入和粘贴的普通文字不进入批次；已经整理过的段不会重复计入。整理沿用正文的语音段处理方式，结果回填原位置，不增加逐字段的应用预览流程。

开始整理时固定本批次的请求、语音段身份、目标与原内容。等待模型返回时切换输入位置，不会把结果写入新位置；新录入的语音留到下一批次。已被手动修改、清除或删除的片段，以及改选固定选项后失效的自定义回答，不能被异步整理结果覆盖。不同题目和批注的内容保持各自归属，原稿始终只读。

原有自动整理阈值也统计整个请求。处理失败不会对同一批次无限重试。控制器仍保留整理撤销能力：只允许在整理后草稿未被继续修改时撤销，且不会立即触发同批次的自动整理；右下角不提供独立撤销控件。

语音段整理和提交前的 Cooking 是不同操作。Cooking 仍只生成补充说明的提交版本，保留原始反馈；提交区明确显示“整理补充说明”及“整理补充说明并提交”。这些操作不表示已经整理全部答案或批注，也不改变结构化反馈的提交语义。

## 写入与恢复

正文语音保留现有语音片段节点和 Action 分组。自定义回答和批注语音追加到对应字符串，保留已键入内容、其它题目、原文锚点、整稿判断和段落标记；不会覆盖选区或自动应用建议到原稿。

前台写入基于最新本地完整草稿，避免未保存输入被服务器旧快照覆盖；后台写入重读目标请求并通过相同 revision/CAS 保存。自定义回答和批注的写入回执保存在草稿 envelope 的 `speechWriteback` 元数据中，与字段更新同时保存，并兼容既有批注回执。丢失保存响应后重试同一操作不会重复追加；相同操作 ID 携带不同内容会报错。

字段语音的来源与范围保存在同一 envelope 的 `fieldSpeechSegments` 中，位置使用 Unicode 标量偏移。手动编辑会移动未受影响的范围，使被修改的范围退出待整理统计。旧字段草稿没有来源信息时保留原样，不通过文本内容猜测哪些字来自语音。

待确认转写使用客户端本地存储恢复。旧版只带 Action 的记录迁移为正文目标；未知目标保留为不可写的待处理内容。客户端本地记录不是跨设备语音同步合同，原始录音也不因此变为请求附件。

## 剪贴板、截图与附件

剪贴板文字进入点击工具栏时固定的文字目标，读取过程中切换目标不改变本次目的地。粘贴使用普通文字来源，不标记为语音，也不进入全局语音整理计数。

剪贴板图片、截图和文件属于请求附件，并保留发起输入框的归属。正文中的采集沿用正文附件引用；自定义回答、批注意见和建议措辞的附件在对应字段旁呈现为轻量文件标签，不把图片或附件标记塞入纯文本内容。切换题目或字段后，已开始的采集仍归原字段；目标失效时明确报告，不能改挂到默认补充说明。

所有采集在开始时固定请求和领域目标，正文目标同时保留 Action。文件选择器打开后再切换输入框，不改变所选文件的目的地。截图窗口结束不等于附件保存完成；附件队列还包括存储与引用写回。正在等待人类选区的截图不会让提交无限等待，而是提示先完成或取消截图。

## 结束输入与提交

发布、批准、取消和 Cooking 准备共享输入检查：停止并排空语音和剪贴板，检查待确认转写，再排空本请求附件操作，最后复核输入是否仍忙，然后冻结并保存草稿。失败保留内容或报告未加入的附件，不把失败当作成功。

附件失败至少阻止并提示一次；用户可以重新导入，或再次主动提交以继续而不带失败附件。待确认或写入失败的语音需明确处理后才可提交。对不支持的工作台，原有只读取消路径保留不解释草稿的语义。

核心边界位于通用的 `domain/inputTarget`、`workbenchFields`，语音专用的 `speechTargetTracker`、`speechDraftQueue`、`speechWriteback`，以及组合层的 `voiceInputContext`、`inputToolsContext`、`draftOperationsController` 和 `requestInputPreparation`。`InputToolbar` 携带明确的目标；`TiptapInput` 提供正文和业务字段共用的编辑基础，`WorkbenchTextField` 组合字段投影、工具栏、附件、字数限制和来源标识。共享控制器仍由 App 挂载，不随批注卡片的展开、隐藏或切换销毁。

## 开发验收

启动 `pnpm dev:web` 后，打开该开发服务器的 `/workbenches.html?type=document_review&voice=1` 或 `/workbenches.html?type=questions&voice=1`。页面使用真实共享控制器、目标队列和领域写回，模拟 ASR 硬件事件与整理模型响应，并隔离待确认转写存储。检查各输入框顶部工具栏，以及右下角左侧头像、右侧状态气泡和条件式整理按钮，再用“开始一段语音 / 完成转写”检查切换落点：同框麦克风暂停、另一框麦克风切换后续语音，当前段仍回填原框。模拟整理会去掉开头的“嗯”等口头词，用于验证跨字段回填，不调用真实模型或麦克风。

真实设备、原生浮窗和截图交互通过 [Playground](../../playground/workbenches/README.md) 验收。模拟输入不证明麦克风、识别模型或桌面窗口能力在当前机器上可用。
