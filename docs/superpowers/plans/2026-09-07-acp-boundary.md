# ACP boundary implementation plan

> **For agentic workers:** Use superpowers:subagent-driven-development to implement and review the bounded tasks below.

**Goal:** Expose application-owned configuration and interaction contracts while keeping ACP version and vendor wire differences inside rambledesk-acp.

**Architecture:** Core defines the application contracts. ACP normalizes runtime advertisements, routes opaque configuration IDs, and translates protocol-specific replies. The UI renders those contracts without legacy ACP source selection or provider checks. Raw SDK access is explicitly isolated for probes.

**Tech Stack:** Rust, official ACP Rust SDK, Svelte/TypeScript, local Node protocol fixtures.

**Spec:** The user's approved architecture evaluation in this conversation: normalize configuration and interactions, isolate private extensions, narrow public API; preserve current behavior and data.

## Global constraints

- Continue the existing `codex/acp-managed-sessions` checkout; preserve all pre-existing work. No commits, branch switches, database migrations or real-account agent runs.
- Existing dynamic capabilities, agent-confirmed values, cancellation, session attribution and response-once guarantees remain mandatory.
- No inferred YOLO mode, new dependencies, runtime plugin system or new crates.
- Live runtime contracts may change together with their callers; stored session identity/history and database formats do not change.
- Generated TypeScript is regenerated by root after integration, never hand-edited.

## Task 1: Normalize session configuration

Files: core `sessions/configuration.rs`; ACP `session_configuration*`; frontend `agents/configuration/*`; corresponding configuration tests/fixtures.

Contract: `SessionConfiguration { options: Vec<SessionConfigOption> }`; `SessionConfigChange { config_id: String, value: SessionConfigValue }`. Legacy modes/models and vendor metadata remain internal. Public IDs are opaque, stable within the session and collision-safe. Option categories retain their actual meaning.

- [x] Adapt configuration integration tests to a single options/change contract. Assert standard precedence, legacy/model routing, colliding IDs, async notifications and refusals.
- [x] Implement internal route mapping and an encapsulated configuration extension; remove frontend legacy selection and public legacy types.
- [x] Run targeted ACP and frontend configuration tests; root updates any remaining shared fixtures/export list.

## Task 2: Isolate private interaction protocols and raw API

Files: ACP `user_input.rs`, `user_input/*`, `connection.rs`, `lib.rs`, raw smoke/tests.

Contract: common `InputSpec` exposes `kind: SessionInputKind` (`Question` or `Plan`) and schema; protocol modules own wire parsing, acceptance and cancellation. Root adds the core enum and updates the event consumer. Central lifecycle code must not contain provider-specific response JSON or bind-by-brand rules.

- [x] Preserve existing source-shaped fixture tests for standard/Grok/Cursor request and cancellation envelopes.
- [x] Move protocol codecs into standard/Grok/Cursor modules with a small internal protocol interface; move request registration out of connection orchestration.
- [x] Expose low-level SDK APIs only through an explicit `probe` namespace; root public exports expose the high-level drivers. Update probe callers.
- [x] Run targeted protocol tests once root's new contracts compile; document any coordination requirements.

## Task 3: Model user interactions explicitly

Files: core session interactions, runtime, driver and application callers; ACP observer/driver; frontend workspace/controller/UI; transports, generated export list and fixtures.

Contract: `SessionInteraction` has common request/session/title/details and a tagged `SessionInteractionKind`: permission with options, question with input, plan with input. `SessionInteractionResponse` has matching permission/question/plan variants. `RespondManagedInteractionInput` contains session_id, request_id and response. One driver `respond_interaction` method and one application action handle responses. Runtime uses `WaitingInput` and snapshots expose `interactions`.

- [x] Add a regression test rejecting a response whose interaction kind does not match; retain duplicate/cross-session/late-response checks.
- [x] Migrate the runtime and transport contracts together, retaining the original pending-request lifecycle and wire response queues.
- [x] Update frontend rendering and status text to distinguish authorization, questions and plan review, sharing the existing generic schema form. Document its supported flat JSON-schema subset.
- [x] Regenerate contracts and run frontend type checks plus core/ACP/local-server/storage tests.
