# ADR 003：Ramble 是统一的采集状态

- 状态：Accepted
- 日期：2026-07-31

## 背景

语音、区域截图、剪贴板和正文编辑原本分别工作。单独能力可用，但用户必须记住每个
工具何时开启，也无法清楚判断当前是否仍在记录一次反馈。产品需要一个与“录音”不同、
比单个输入工具更高层的概念。

## 决策

Ramble 是附着于当前未提交 Feedback Request 的统一采集状态：

```text
idle ──开始/继续──> starting ──全部就绪──> active
  ^                                      │
  └────────────── stopping <──停止───────┘
                         └──失败──> error ──重试──> starting
```

- `开始 Ramble` 同时启动本地流式语音和 Windows 剪贴板监听，并激活区域截图入口；
- `Ctrl + Shift + R` 在其他软件前台时也可开始、暂停或继续；
- `Ctrl + Shift + 1` 只在 `active` 时执行区域截图；
- 停止只暂停采集，不删除正文、附件或已捕获上下文；提交前可反复继续；
- 切换 Request、重新载入或提交前必须先停止当前 Ramble；
- 任一必需采集器启动失败时回滚已启动的采集器，不进入半激活状态；
- 麦克风会话意外停止时同时停掉剪贴板监听，避免 UI 显示与实际状态分裂。

## 文档流映射

- 稳定语音片段作为普通段落写入正文；
- 剪贴板文字作为带捕获时间的引用块追加，视觉上与用户正文区分，但仍可编辑；
- 剪贴板图片和区域截图均存为不可变附件，用 `attachment://<id>` 在 Markdown
  文档流中内联显示；
- 自动捕获追加到文档末尾，主动区域截图仍插入用户最后的编辑光标位置。

## 隐私与边界

- 剪贴板监听只在 `active` 状态运行，每次继续时以当时的 sequence number 为基线，
  不导入开始前已有内容；
- 监听只读，不清空、不改写系统剪贴板，也不读取 Windows 剪贴板历史；
- 文字最多捕获 50,000 字符，图片沿用 20 MiB 附件限制；
- 所有内容保持本地，只有用户提交 Feedback Package 后才进入既有反馈交付路径；
- UI 必须持续显示麦克风、截图快捷键和剪贴板是否处于激活状态。

## MVP 取舍

Windows 使用轮询 `GetClipboardSequenceNumber` 后按需读取新内容。暂不引入系统级
低层键盘钩子、剪贴板历史管理、来源应用识别、跨设备同步或可编排采集插件。
